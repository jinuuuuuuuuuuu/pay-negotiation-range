# 협상 구간 기능 제안 (팀 공유, 11-22) — 처음 보는 사람용

> 상태: **11-22 팀 확정·구현 완료** (상한 정의 승인, 이름 "상한", 표시 한도 10% 초과, 비교군 적자 시 "업계 적자로 인한 상한 산출 보류", 기능 2 = 「인상안 협상 구간」, 기능 4 = 「업계 불황 대비 점검」). 아래는 제안 당시 설명입니다. 구현된 숫자는 결정표 14장 기준이고, 판정 순서가 확정되면서 "상한 ≥ 하한" 비율은 39% → 47%(상한이 계산된 1,645곳 기준)로 바뀌었습니다. 맨 아래 "팀이 정할 것"은 1~4번이 확정되었고 5번(회귀 분석)만 남았습니다.

## 한 줄 요약
성과급·임금 인상 요구가 왔을 때 **"몇 %에서 몇 %까지가 협상 구간인가"**를 데이터로 보여 주는 기능을 에이전트의 중심으로 삼자는 제안입니다.

## 1. 왜 방향을 바꾸나
현업 급여·노무 담당 선배에게 프로젝트 피드백을 받았습니다.
- PPT에서 에이전트가 **무엇을 푸는지** 보이지 않는다.
- 근로자 입장만 대변하는 것처럼 보인다. 경영진에게도 도움이 되어야 한다.
- 현업은 "동종업계가 N% 올렸으니 우리도 그 근처"로 가장 많이 비교한다.
- "여력이 있으니 더 준다"는 가정은 틀렸다. 여력이 있어도 경영진은 배당·재투자를 먼저 생각한다.
- 인상 비용 계산은 데이터 분석이 아니라 그냥 계산이다.
- 선배가 제안한 문제 정의: "성과급·임금 인상 요구가 왔을 때, 원만한 노사 합의를 위한 적정선을 도출할 지표는 무엇인가?"

→ 합의는 교섭력으로 정해지므로 정답 한 점은 못 줍니다. 대신 **양쪽이 각자 내세울 근거를 숫자로 보여 주는 구간**을 만들자는 것이 이 제안입니다.

## 2. 구간이란 무엇인가
```
        하한 ├──────── 협상 구간 ────────┤ 상한
   "이 아래면 업계에 뒤처짐"          "이 위면 업계보다 부담이 큼"
   (노측이 내세울 근거)               (사측이 내세울 근거)
```
- 하한과 상한은 **데이터가 계산**합니다. 사용자는 회사만 고르면 됩니다.
- 하한은 "누구 편 숫자"가 아니라 **노측이 쓸 수 있는 근거**이고, 상한은 **사측이 쓸 수 있는 근거**입니다. 구간은 양쪽 모두에게 쓰는 자료입니다.

### 먼저 알아야 할 용어
- **비교군:** 우리 회사와 같은 업종에서 매출·1인당 자산이 비슷한 20개 회사. 이미 만들어져 있고 산술식 최종본 1장에 규칙이 있습니다.
- **비교군 인상률:** 비교군 20곳의 최근 3년 1인당 급여 연 증가율의 중앙값. 전체 회사 중앙값은 3.8%입니다.
- **이익÷급여:** 급여 1원당 영업이익이 얼마인지. 클수록 같은 인상을 이익이 쉽게 감당합니다.

### 하한 = 비교군 인상률
- 이미 계산되어 있고(`formula.peer_growth`, MVP 입력 파일의 "비교군 인상률" 열, 2,205곳 중 2,091곳) **사용자가 입력하지 않습니다.** 다른 값(협회 조사 등)으로 덮어쓸 수는 있게 합니다.
- 근거(추가 가설검정 H7, WPS 2015~2023): 임금이 10% 높은 회사는 자발적 이직률이 0.45%p 낮습니다. 동종 대비 임금 위치 하위 20%의 이직률은 17.8%, 상위 20%는 12.7%입니다. 단, **같은 회사 안에서 임금을 올렸을 때 이직이 줄어드는지는 확인되지 않았습니다.**
- 한계: 1인당 급여 증가율이라 기본급 인상률 자체는 아닙니다(성과급·승진·인력 구성 변화가 섞임).

### 상한 = "업계와 같은 부담 수준" (제안)
```
상한 = 업계 인상률 × (우리 이익÷급여) ÷ (비교군 이익÷급여 중앙값)
      (3년 합산 기준, 마지막 해 적자 전환 직전을 넘지 못하게 제한)
```
- 뜻: 인상이 영업이익에서 차지하는 비중을 **비교군과 똑같이 맞췄을 때의 인상률**입니다.
- 쉬운 예 (가상 숫자): 업계 인상률 5%, 비교군 이익÷급여 0.5
  - 우리 이익÷급여가 1.0이면 상한 = 5% × 1.0 ÷ 0.5 = **10%** (이익 체력이 두 배라 두 배까지 올려도 업계와 같은 부담)
  - 우리가 0.25이면 상한 = **2.5%** (체력이 절반이라 업계 인상률만 따라가도 부담이 더 큼)
- 실제 회사 예: 기아는 하한 6.6%, 상한 약 22% / LG전자는 하한 3.1%, 상한 약 0%(이익이 거의 없음)
- **상한이 하한보다 낮은 회사(61%)**가 많습니다. 이때는 "구간 없음"이 아니라 "업계만큼 주면 우리 부담이 업계보다 크다"는 신호로 보고, 고정 인상 대신 **이익연동 전환(기능 3)**을 검토하라고 안내합니다. 상한이 하한보다 높은 회사(39%)는 업계 수준 이상도 업계만큼의 부담으로 감당되는 회사입니다.
- 진단의 지급 여력과 일치합니다. 상한 ≥ 하한인 비율이 여력 있음 79%, 보통 18%, 제약 1%입니다.

### 상한을 왜 이렇게 정했나 (실패한 방법들)
"감당 가능한 한도"를 회사 한 곳의 숫자로 정하려고 4가지 규칙을 시험했지만 모두 안정적이지 않았습니다.

| 시험한 규칙 | 결과 |
|---|---|
| 영업이익률의 평소 출렁임만큼 | 상한 중앙 45%로 사실상 상한이 아님 |
| 비용 ≤ 영업이익의 10% | 61% 회사에서 상한이 하한보다 낮음 |
| 1인당 부가가치 증가율만큼 | 회사마다 ±20%로 널뛰고 65%가 상한 < 하한 |
| 비교군의 이익 대비 부담(중앙값) | 70%가 상한 < 하한 |

이유는 "어디까지 감당하나"가 배당·투자와 견주는 경영 판단이라 데이터로 못박기 어렵기 때문입니다. 그래서 감당 한도 대신 **"업계 기준으로 맞춘 선"**을 상한으로 제안합니다.

### 상한의 한계 (공유할 때 꼭 말하기)
- 비교군이 올린 부담이 적당했다고 **가정**한 "업계 균형선"이지 감당 한도가 아닙니다. 이름도 "상한" 대신 "업계 균형선" 같은 표현이 오해가 적을 수 있습니다.
- 비교군 이익이 0 이하인 446곳(바이오 등)은 계산하지 못합니다.
- 이익이 큰 회사는 상한이 20~60%까지 나오므로 "10% 초과" 같은 표시 한도가 필요합니다.

## 3. 노조안·회사안은 어디에 들어가나
**노조안·회사안은 하한·상한과 다른 것입니다.** 하한·상한은 데이터가 정하는 구간이고, 노조안·회사안은 **사용자가 입력하는 제안**(예: 노조 8%, 회사 3%)입니다.
```
 회사안 3%     하한 4.5% ├──── 구간 ────┤ 상한 6.8%        노조안 8%
    ●                                                         ●
 (하한 미달)                                             (상한 초과)
```
- 구간이 메인 결과이고, 안 비교는 "구간 위에 안을 올려 보는" 확인 기능입니다.
- 회사안이 하한 아래면 노측이 "업계에 뒤처진다"로, 노조안이 상한 위면 사측이 "업계보다 부담이 크다"로 반박할 수 있다는 것을 보여 줍니다.
- 안마다 기존의 비용 계산(영업이익률 하락, 내년 숫자, 업계 대비 위치)이 그대로 붙습니다.

## 4. 에이전트 기능 구조
| 기능 | 하는 일 |
|---|---|
| 1 진단 | 업계 대비 임금 위치, 지급 여력 (그대로) |
| 2 인상 결정 | 맨 앞에 **하한~상한 구간**, 그 위에 노조안·회사안 비교 |
| 3 이익연동 전환 | 구간이 안 맞는 회사(상한 < 하한)에게 고정 성과급 대신 이익에 연동하는 대안 |
| 4 불황 대비 점검 | 이름을 "스트레스 테스트"에서 변경(코드 함수명은 유지). 불황이 오면 그 인상안을 버틸 수 있는지. **업황 충격은 이 기능에만 둡니다** |

확정된 것: 성과급 부대비용 c = 0.10.

## 5. 팀이 정할 것
1. 상한을 위의 "업계와 같은 부담 수준"으로 할지 (아니면 다른 방식)
2. 상한 이름을 "상한" 대신 "업계 균형선" 등으로 바꿀지
3. 표시 한도(10% 초과)와 계산 불가 회사 처리
4. "불황 대비 점검" 이름 확정
5. 별도: 실제 인상률을 결정해 온 지표 회귀 분석(구간의 기준점 "업계 관행대로면 N%")을 할지

## 6. 확정되면
`formula.py` 함수와 테스트 → 결정표 기록 → MVP 입력 열 추가 → 스토리라인 슬라이드 2장 → 화면 목업 → 선배 재확인
